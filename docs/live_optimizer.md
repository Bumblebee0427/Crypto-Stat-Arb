# 三因子 EWMA14 / 90 天实盘接入

固定模型名为 `core_w90_f14_r14_cv_diagonal`。计算器使用与研究相同的 `estimate_grid`、`RiskSpec` 和 `solve_weights`；当前调用链与 B0–B5 的历史通用入口独立。

| 设置 | 实盘值 |
| --- | --- |
| 因子 | CMKT、CSMB、CMOM |
| 风险窗口 | 最近 90 个日历日 |
| 因子 / 残差 EWMA 半衰期 | 均为 14 天 |
| 收缩 | 向对角矩阵收缩；前 80% 拟合、后 20% QLIKE 验证 |
| 收缩强度候选 | 0、0.1、0.25、0.5、0.75、1；因子和残差分别选择 |
| 原始优化解单币边界 | 原始权重的 0.5–1.5 倍，禁止翻方向 |
| 实际应用 | 75% 原始权重 + 25% 优化解，故相对原权重为 0.875–1.125 倍 |
| 方向与预算 | 选币池、多头预算、空头预算均保持原策略设置 |
| 目标项 | Alpha − gamma/2 × 方差 − 成本 − 预期资金费 − 稳定性惩罚；gamma=2，eta=1e-5，单边成本 8 bp |
| 资金基准 | 使用策略现金预算作为优化权益基准，保持研究中的 2 倍名义权重尺度 |
| 频率 | 每日北京时间 08:00 换仓；不运行研究中的每小时 10% 再平衡阈值 |

当前名义目标为 `2 × min(1500, 0.5 × 账户权益) × gross_allocation`。正常多空时 `gross_allocation=1`；原策略的 BTC 过滤减少空头预算时不重新放大。步长取整、低于最小名义金额的同向调整保留，以及实际持仓漂移仍按原执行规则处理，实际持仓金额可能偏离目标，开仓继续检查交易所限额与可用保证金。

## 数据更新

`tools/update_live_optimizer_data.py` 读取币安官网的公开接口：

- `https://www.binance.com/bapi/apex/v1/friendly/apex/marketing/complianceSymbolList`：当前市值信息及 CMC 唯一 ID。
- `https://www.binance.com/bapi/composite/v1/public/promo/cmc/cryptocurrency/quotes/historical`：CoinMarketCap 来源的历史 USD 市值、价格和流通量。
- `https://fapi.binance.com/fapi/v1/klines`：官方已结束日线的价格与成交额。
- `https://fapi.binance.com/fapi/v1/fundingRate`：已结算资金费。

使用历史报价，不使用“当前流通量 × 历史价格”回填。UTC 零点 D 的报价记录为 D−1 的收盘观测，继续按研究的 source day +2 天规则处理可用时间，并限制市值过期填充。它是修订后的历史序列，不能宣称拥有真实历史发布版本。

原始响应、哈希与观测时间留在本地 `data/`，新增数据不覆盖原冻结回测。市值缺失的因子组成币不会被伪造市值；因子池继续使用已知且有效的组成币。实盘选出的新币仍可利用其价格历史估计暴露；样本不足时固定在原权重。最新因子必须完整且覆盖最近决策日，90 天窗口至少有 60 条完整观测。

初始化示例（本地目录自行准备）：

```bash
cd backtest
../.venv/bin/python tools/update_live_optimizer_data.py \
  --root data/live_optimizer \
  --legacy-cap-root /path/to/legacy/coin-cap \
  --seed-closes /path/to/frozen/daily_closes.parquet \
  --seed-quotes /path/to/frozen/daily_quote_volume.parquet
```

## 每日生产与交易机校验

`tools/run_live_optimizer.py --config /path/to/private/live_config.json` 在 UTC 00:00 开始更新数据，等待首尔完整 v3 选币快照，读取交易机只读持仓与权益、计算资金费预测，再生成当天权重文件。重用已有行情和市值时下载近几天的重叠区间。

私有配置包含 `data_root, legacy_cap_root, seed_closes, seed_quotes, ssh_key, trade_host, trade_root, seoul_host, seoul_root, env_file`。地址和密钥路径由部署环境配置；交易所密钥只在交易机原有环境文件内读取，不传回计算机。`--preview --skip-refresh` 可执行只读预演，预演文件带有不可交易标记。

交易机每日执行器在生成订单前调用 `optimizer_overlay.load_and_apply`。它检查完整哈希、原始快照 ID、当日边界、生成时间、数据截止时间、当前持仓哈希、预算变化、币池、方向、权重边界与两边预算。生成的派生信号保留 `base_snapshot_id`，账本记录模型、优化文件 ID 和回退状态。

启动配置 `optimizer/enabled.json` 指明固定模型。收到完整原始信号后，最多等到其生成时间后 120 秒，并且不晚于北京时间 08:24:45；预留三个五秒轮询机会执行原始权重。等待文件时不反复读取账户。缺失文件超时，或当前信号的优化文件明确失败、校验失败，立即使用原策略权重；不因此清仓。原始信号暂未就绪时等待至 08:25，期间不改动原仓；到期仍无合格当日信号，才在账户检查通过后执行只减仓清仓。账户不一致或订单状态不明时停止新增订单并先对账。信号发布、决策截止 08:25，已开始的开仓最晚截止 08:30。信号和优化文件仍检查生成时间新鲜度，不放宽数据质量。可通过关闭该启动配置回到原始分配，资金预算独立保留。

生产定时器每天 UTC 00:00:05 / 北京时间 08:00:05 运行；交易机原每日执行定时器负责下单。算法计算不直接调用订单接口，候选文件通过 SSH 原子投递，文件归属于交易服务用户且权限为 0600。

## 历史 Alpha 预训练与月度更新

历史数据可以用于预训练，无需重新积累一年实盘。`bootstrap_live_alpha_history.py` 从逐笔 ID 重建上一完整 UTC 小时阈值的 v3 日因子，再按线上规则计算 12 天线性衰减、8/4 天小单因子、599 小时成交额与选币池。历史普通永续、稳定币和杠杆代币的范围与实盘对齐；明确排除 `TRADIFI_PERPETUAL`，不使用当前 `TRADING` 状态筛掉历史退市币。历史合约分类使用冻结的官方元数据，原始发布版本仍不完整。新币和缺失观察的处理与线上发布器保持一致；不把旧版 v2 因子标记成 v3。

Alpha 使用多、空分别拟合的 Ridge，输入为入选池内 `main_rank` 和 `small_rank`，目标为各方向、各日去均值后的未来价格收益；训练目标按 1%/99% 缩尾，各日等权，Ridge penalty=1，预测再乘 0.5。训练窗口为 365 天，每个方向至少有 362 个成熟样本日。CMKT、CSMB、CMOM 用于协方差估计，与这两个预期 Alpha 特征的用途不同。

模型的训练截止时间固定为 UTC 月初，仅使用此前已成熟的标签。历史重建把接收时间限制到决策日 00:08，收益基准使用已校验 SHA256 的币安官方 00:10–01:00 固定窗口 VWAP，并保守地在次日 01:01 才允许标签进入训练。原定 00:10 单分钟基准遇到零成交，因此在查看策略收益之前统一改为固定窗口，不使用零成交 K 线的旧收盘价填补。`repair_alpha_market_history.py` 可从校验过的官方分钟档案补齐截断的小时行情，避免把档案起点当成上市日期；未观察到的小时保持缺失。缺失标签保持缺失并单独统计；验证区间内缺少所需执行价格会阻止发布。

`validate_live_alpha_history.py` 按月向前验证，比较原权重、预期 Alpha 为零的优化器、加入历史训练 Alpha 的优化器。账户使用初始 3,000 USD 和当前资金预算规则，包含交易费用与资金费，输出 Sharpe、Sortino、回撤、成本翻倍、剔除最佳增量日及 7 天分块 Bootstrap。历史捕获与原始发布版本不完整、交易数量取整、滑点和资金费估值粒度等限制随报告记录。自动退市按实际停止交易时间结算并收取退出成本；无法恢复精确的 1,800 秒平均指数时，用完整官方指数分钟 OHLC 的均值上下界分别重放，两个边界均需通过原性能条件。退市不足 24 小时的样本不伪造成 24 小时训练标签，其他未知执行价格仍会阻止发布。此验证不等于完整 2021–2026 实盘 v3 重放。

只有通过声明的验证条件，`publish_live_alpha_release.py` 才原子安装历史训练集。每日生产器校验训练文件、验证报告、参数与数据可用时间，合并新收集的线上样本；模型指纹进入权重文件。历史文件无效或训练不足时，预期 Alpha 回到零，风险、成本与资金费优化仍可继续。

每日线上标签的起点使用信号发布后下一完整分钟的 VWAP；历史已发布快照也可以用 `import_published_alpha_history.py` 补录，衔接逐笔回放与后续增量数据。实际发布分钟与固定历史基准存在差异，报告中保留该限制。

`complete_live_alpha_bootstrap.py --config /path/to/private/history_config.json` 可串行执行重建、价格准备、风险估计、验证、报告与通过后的安装，并进行不可交易的生产预演。私有配置指定历史目录、逐笔根目录、官方分钟档案根目录、行情文件、官方合约分类 `exchange_info`、可选 `repair_symbols`、市值目录和既有生产配置；不包含在仓库中。逐日结果支持断点续跑，源文件改变时重算受影响的结果。已准备好全部输入时，私有配置 `resume_validation=true` 可跳过重建，仍会重新执行价格、标签与时间检查。

实盘继续每日换仓，实际混合比例仍为 25%；历史研究的每小时再平衡和 v2 回测收益不能直接作为此次实盘收益预期。


## 2026-10-21 历史验证结果

从 2025-06-18 至 2026-10-07 重建了 477 天逐笔因子。独立验证区间为 2026-07-01 至 2026-10-07，共 99 天；四次月初拟合的多、空两边各有 364 个成熟训练日，时间与输入检查通过。接入器合并历史与实际发布增量样本后，10 月模型指纹与验证模型一致。

当前账户预算口径、单边 8 bp 成本、每日换仓、25% 优化权重混合下，结果为：

| 方案 | 累计收益 | Sharpe | Sortino | 最大回撤 |
| --- | ---: | ---: | ---: | ---: |
| 原等权 | 28.51% | 3.269 | 6.081 | -6.97% |
| 风险/成本/资金费优化，Alpha=0 | 25.36% | 3.000 | 5.327 | -7.87% |
| 同一优化器加入训练 Alpha | 25.42% | 2.997 | 5.320 | -7.95% |

加入 Alpha 的平均每日增量为 +0.0605 bp，7 天分块 Bootstrap 95% 区间为 [-0.2437, +0.4761] bp。剔除最大增量日后为 -0.0138 bp/日。NFP 退市结算的两个指数价格边界下，Sortino 与剔除最佳日条件均未通过；成本翻倍时训练 Alpha 的累计收益也略低于零 Alpha 对照。

因此历史训练与向前验证框架已经完成，但该训练 Alpha 未发布到实盘；现有 25% 风险/成本/资金费优化配置继续运行。该区间也不支持“优化器一定优于原等权”的结论。不在这一验证区间反复调参后再宣称独立样本外改善。

历史重建存在价格执行窗口与原始数据发布版本差异；10 月 8 日重建选币与实际发布选币有 36/37 个方向持仓一致，一个多头不同。以上是固定窗口回放结果，不是实盘收益或完整历史快照重放。原有公开收益图仍是先前回测图，不替换成这次研究图。


## 发布重算的内存约束

逐币原始成交重算按 UTC 小时处理，只累计分钟归约结果，避免拼接整天成交。单小时输入超过 64 MiB 或重算失败时，按既有合格池规则隔离该币；不截断成交、不修改资金流公式。重算仍校验重复 ID 冲突、小时边界、跨小时 ID 重叠、源文件修订和经济成交总数。发布服务采用有次数限制的失败重试，原交易截止时间继续生效。

2026-10-24 故障分流：单币数据质量或重放资源失败按币排除，继续在达标池选币；优化器失败退回原始权重；目标计划或开仓预检查失败在 08:25 前保留原仓并重试，超过决策截止才按无可执行信号策略处理。账户审计失败不提交任何订单；下单回执不明则停止后续提交、查询原订单 ID，重启不重复 POST。计算服务超时同步延至 30 分钟；发布服务与执行定时器均需部署相同的 `live_schedule.py`。
